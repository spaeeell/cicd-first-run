# Отчёт — первая практика CI

## 1. Цель работы

Изучить работу CI на GitHub Actions: автоматическое тестирование, сборку сайта, сохранение артефакта, обнаружение ошибки и повторную проверку после исправления.

Репозиторий: https://github.com/spaeeell/cicd-first-run

## 3. Намеренная ошибка

Перед изменением я предположил, что замена `href="style.css"` на `href="missing.css"` приведёт к падению теста `test_stylesheet_exists`, а сборка сайта и сохранение артефакта будут пропущены.

[Lesson CI #2 — failed](https://github.com/spaeeell/cicd-first-run/actions/runs/42364638288)

Коммит: `7b70831a7029ab52b3e0cae1bd512ea74be0036e`

Фактический результат:

- Три теста прошли успешно, один завершился ошибкой.
- Упал `test_stylesheet_exists`.
- В логе обнаружена строка `AssertionError: False is not true : Missing stylesheet: missing.css`.
- Шаг `Run tests` завершился с `exit code 1`.
- `Build site` и `Save site artifact` получили статус `skipped`.

Причина ошибки: HTML ссылается на несуществующий CSS-файл.

## 4. Исправление ошибки

Я восстановил `href="style.css"` и создал отдельный коммит `restore stylesheet link`.

[Lesson CI #3 — success](https://github.com/spaeeell/cicd-first-run/actions/runs/42364829518)

Коммит: `bb02dae3921b7d0232dabe6813377b2280a82e2c`

После исправления workflow успешно завершился. Предыдущий неуспешный запуск остался в истории GitHub Actions, поскольку он относится к другой версии кода.

## 5. Эксперимент с номером аудитории

Я изменил `Аудитория: 301` на `Аудитория: 302` отдельным коммитом.

Прогноз: CI останется зелёным, поскольку имеющиеся тесты не проверяют правильность номера аудитории.

[Lesson CI #4 — success](https://github.com/spaeeell/cicd-first-run/actions/runs/42364947898)

Коммит: `5ecfae554f31295fdd959ae491b5a2bcb7f8f537`

Прогноз подтвердился: workflow успешно завершился.

Это показывает, что успешное прохождение тестов подтверждает только соблюдение проверяемых условий, но не гарантирует отсутствие других ошибок.

## 6. Где выполняются проверки

Тесты выполняются на `runner` — вычислительной среде GitHub Actions. В нашем workflow используется `ubuntu-latest`.

После каждого `push` GitHub запускает workflow и сохраняет результаты проверки, журналы выполнения и статусы шагов в интерфейсе Actions.

Артефакт `lesson-site` содержит результат сборки сайта. Его скачивание не означает публикацию сайта в интернете.

## 7. Вывод

В ходе работы я настроил автоматическую проверку сайта через GitHub Actions, получил успешный запуск, намеренно вызвал ошибку, изучил её причину и подтвердил успешное исправление.

Эксперимент с номером аудитории показал ограниченность автоматических тестов: зелёный CI не означает, что проверены все требования к приложению.
